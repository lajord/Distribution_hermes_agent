# Stepers — Hypothèses & questionnements

> Dernière révision : 2026-09-12

## Comment ce fichier fonctionne

> Directive pour Hermes.

Ce fichier est **vivant**. Ce ne sont pas des vérités : ce sont des **hypothèses
et des questionnements ouverts** sur ce que doit être Stepers — l'ICP, la valeur,
le produit, le positionnement.

Règles :

- **On ajoute les nouvelles hypothèses à la suite**, on ne les efface pas.
- On **prend des notes** et on ajoute des **commentaires** au fil du temps.
- On **met la data** : chaque fois qu'un signal (DM, call, objection, perf de
  contenu, inscription, comportement utilisateur) éclaire une hypothèse, on
  l'inscrit ici comme preuve.
- Hermes peut **remplir, adapter, faire évoluer** ce fichier : confirmer,
  invalider ou reformuler une hypothèse, en proposer de nouvelles.

**Le marché a toujours raison. Il faut l'écouter.** L'objectif n'est pas de
défendre l'idée actuelle de Stepers, mais de faire émerger, à partir des signaux
réels du marché, le problème et la proposition de valeur qui résonnent le plus
fort auprès de l'ICP. Voir aussi le « Principe important » dans [company.md](company.md).

### Convention pour une entrée

Pour chaque hypothèse / questionnement, au fil de l'eau :

- **Statut** : ouvert / en cours / confirmé / invalidé / à reformuler.
- **Notes & commentaires** : observations, réflexions.
- **Data / preuves** : signaux concrets (source + date) qui appuient ou
  contredisent l'hypothèse.

# Questionnements Stepers

## 1. Quel est réellement le meilleur ICP ?

Quel type de SaaS founder ressent le plus fortement le problème que Stepers cherche à résoudre ?

- À quel niveau de maturité du SaaS ?
- Avec quelle stack actuelle ?
- Avec combien d'emails / d'automatisations ?
- Quel est le moment précis où Stepers devient nécessaire plutôt que simplement "nice to have" ?

## 2. Quelle est réellement la valeur principale de Stepers ?

Quelle douleur est suffisamment importante pour pousser quelqu'un à adopter Stepers ?

Est-ce principalement :

- centraliser tous les emails du SaaS ;
- sortir la logique email du code ;
- avoir plus de visibilité ;
- construire plus rapidement des lifecycle emails ;
- gérer transactionnel + lifecycle ensemble ;
- pouvoir facilement analyser et améliorer le système ?

**Le marché doit déterminer quelle valeur compte réellement le plus.**

## 3. Que doit réellement être le produit ?

Quelle est la version de Stepers qui apporte le maximum de valeur à cet ICP ?

Notamment :

- quelle place pour les emails transactionnels ;
- quelle place pour les workflows ;
- quelle importance pour les events ;
- quelle importance pour les analytics ;
- quelle place réelle pour l'agent IA.

L'objectif est d'éviter de construire des fonctionnalités simplement parce qu'elles semblent logiques : **le produit doit évoluer selon les problèmes réellement observés chez les utilisateurs.**

## 4. Pourquoi choisir Stepers plutôt qu'une alternative ?

La question centrale de positionnement :

**Pourquoi quelqu'un utiliserait Stepers plutôt que continuer avec Resend + son propre code, ou utiliser Loops / Customer.io ?**

Il faut déterminer quelle différence compte réellement pour le marché :

- simplicité ;
- centralisation ;
- transactionnel + lifecycle ;
- IA ;
- pricing ;
- meilleure expérience pour les SaaS founders ;
- autre chose encore non identifiée.

La réponse à cette question n'est pas encore totalement validée et doit émerger des conversations, usages et achats.
